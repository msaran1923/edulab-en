# Math Problem Explainer Video (edu-math-video)

Turns one math problem into a 16:9, 1920×1080 MP4 with English/Turkish voice-over + bilingual subtitles + hand-drawn notebook-style animation.

Pipeline (one folder per video):

```
script.json ──build_audio.py──► build/timeline.json + build/mix.wav + ../<name>.srt
     (narration)   (TTS + synthesized music)          │
anim.js + engine.js ◄─────────────────────────┘ (animation driven by narration timestamps)
     └──node render.mjs video──► ../<name>.mp4
```

**Core principle: the picture follows the narration, and the figure "explains the problem."** For every narration line there is an action on the figure that demonstrates that line of reasoning (equal segments slide onto each other, congruent triangles overlay, camera tweens to a top view, a moving point moves…). Each animation is timed with `S.at(k, f)` ("the moment the k-th narration line starts"), never with hard-coded seconds.

**This skill contains all the code**; do not copy files from other projects:
- `template/`: a complete runnable sample project (right-triangle median-to-hypotenuse problem). `engine.js` is the generic engine (do not change), `anim.js` / `script.json` / `episode.json` / `problem.png` must be rewritten for each problem.
- `shared/pron.py` + `shared/pron.json`: pronunciation control (for engines that need it).
- `examples/cone-parallel/`: complete solid-geometry example (anim.js + storyboard.md + script.json): camera tilt ↔ top view, lateral surface unrolls into a sector, alternate interior angles rotate, plane translation. Read it first for solid geometry, circles, or multi-part problems.
- `scripts/`: `new_video.sh` (create project), `setup_check.sh` (check environment), `make_problem_png.py` (text problem → image + highlight boxes), `problem_boxes.py` (screenshot → highlight box coordinates), `contact_sheet.py` (contact sheet review of screenshots).

Below `SKILL` = the directory containing this file, `WS` = **the user's current working directory (`$PWD`)**: the video folder is created here, and mp4/srt are also output here. **Do not switch WS just because another directory already has `.env`, `node_modules`, or `pron.json`**. `PROJ` = this video's folder, `PY` = the python reported by `setup_check.sh`.

## Rules that must be followed

**Non-zero exit code means not finished.** `--check` exit code 1 (even if only one ⚠ polyphone remains), `motion` exit code 1, or problems in screenshots must be fixed before continuing. Do not write "just a warning, doesn't affect" and proceed.

1. **Strictly follow the 11 steps below in order; the "pass criteria" of each step must be met before moving to the next.** Do not skip steps.
2. **Explain the problem clearly first.** The first scene must show the original problem image (screenshot or generated by `make_problem_png.py`), the narration reads each condition, and each condition is boxed on the figure as it is read.
3. **`tts` field must be speakable text.** No Arabic digits, `= + − × ÷ / ^ √ ∠ △ ∥ ° ( )` etc. symbols: write `AC=3` as `AC equals three`, `x²` as `x squared`. The subtitle `zh`/`en`/`tr` field keeps normal mathematical notation. `--check` will error and stop you.
4. **Pronunciation must be fixed** (especially for Chinese polyphones if using GLM-TTS; for edge-tts less critical but still check). Before calling TTS, `--check` must show `unfixed rare/polyphone characters: 0` and `script errors: 0`.
5. **API Key is provided only by the user.** If `GLM_API_KEY` is missing, first ask the user: configure the key (best quality, recommended), or use the fallback engine (edge-tts / macOS `say`). Do not invent keys, model names, or endpoints, do not print the key.
6. **All visual content stays within y ≤ 860** (y≈914~1044 is the subtitle box). Graphics on the left half x 60~900, derivation text on the right board `board()`.
7. **Write the storyboard first, then the animation.** `storyboard.md` plans "point / move / leave" for each narration line; `node render.mjs motion` must pass.
8. **Preview for free before spending money.** Use `--preview` + `stills auto` to check layout, then run real TTS.
9. **Verify by looking at the images.** After every render of screenshots open `build/sheet.png` and check with your eyes (use the image viewing tool). Report what you actually saw.
10. **Do not modify `engine.js`** unless the user asks for a style change; write new graphics as functions in `anim.js`.
11. **Do not copy `node_modules` or `package*.json` into the video folder**; dependencies are installed once at the `WS` root and shared by all videos.

## 11 Steps

### Step 1: Understand the problem and solve it correctly yourself
- Get the problem text (read the image first if there is a screenshot). **Solve it completely yourself and verify**, write down: list of given conditions, what is asked, key ideas (1–2), each calculation step, final answer, verification method.
- If the answer is uncertain or the problem is unclear, ask the user; do not guess.
- **Pass criteria:** You can explain it in 3–6 "scenes", each scene has one clear purpose sentence; answer has been verified.

### Step 2: Create the project and check the environment
```bash
bash SKILL/scripts/new_video.sh "$PWD" <ascii_folder_name>
bash SKILL/scripts/setup_check.sh WS/<ascii_folder_name>
```
- `new_video.sh` links `pron.py`/`pron.json` to the shared lexicon and links existing `node_modules` if found (does not copy); if not found you need to `npm install` under `WS`. Python packages: `PY -m pip install --user numpy requests pypinyin pillow`.
- If `GLM_API_KEY` is missing: **stop and guide the user** according to the setup reference (recommend `~/.config/math-problem-video/.env`). If the user has no key or does not want to configure one: `TTS_ENGINE=auto` (default) automatically falls back; get consent before installing edge-tts.
- **Pass criteria:** `setup_check.sh` outputs `ALL OK`.

### Step 3: Test TTS (verify key and voice)
```bash
cd PROJ && PY build_audio.py --say "Hello, let's look at a math problem."
```
- Success prints `WROTE build/say_xxxx.wav` and `voice: ...` (`edge:` / `say:` prefix = fallback engine).
- The first time you make a video for this user, give the wav path to the user to listen and confirm the voice.
- **Pass criteria:** A wav was generated.

### Step 4: Prepare the problem image `problem.png` and highlight boxes
Choose one (details in the animation reference):
- **Text only**: `PY SKILL/scripts/make_problem_png.py --text "full problem" --mark "condition1" "condition2" ... "asked" --out PROJ/problem.png`
- **Screenshot**: copy to `PROJ/`, crop if needed with `problem_boxes.py`, then grid/check.
- Fill size and boxes into the top of `anim.js` as `PROBLEM`.
- **Pass criteria:** You opened `*.preview.png` or `*.check.png`, text is complete, each box exactly covers the corresponding text.

### Step 5: Write `episode.json` and `script.json`
- `episode.json`: `title`, `output_name`, `pop_scenes`.
- `script.json`: array of scenes, each `{"scene": "english_id", "lines": [{"zh","tts","en"}, ...]}` or with `tr`. First scene `intro` reads the problem, last scene `outro` reviews + states the answer.
- Each narration line ≤ 36 character widths, one thing per line.
- **Pass criteria:** Valid JSON; every scene id has a planned picture.

### Step 6: Write the storyboard `storyboard.md`
Plan "point / move / leave" for each line. "Move" must be a meaningful action that shows the reasoning (equal → copy and slide to coincide, congruent → overlay triangles, 3D ↔ top view → camera tween, etc.).
- **Pass criteria:** Every line has a row; figure list is complete.

### Step 7: Pronunciation and script check, fix to 0
```bash
cd PROJ && PY build_audio.py --check ; cat build/pron_report.txt
```
- **Pass criteria:** `unfixed rare/polyphone characters: 0` and `script errors: 0`, exit code 0.

### Step 8: Write `anim.js`
Implement according to the storyboard. Structure: `PROBLEM`, `TAGS`, figure functions, `SC.<id> = (lt, S) => {...}`.
- Each element appears at the moment the narration mentions it: `S.P(S.at(k, f), duration)`.
- **Pass criteria:** `PY build_audio.py --check` has no ERROR.

### Step 9: Free preview: motion check + layout check
```bash
cd PROJ && PY build_audio.py --preview && node render.mjs motion && node render.mjs stills auto && PY SKILL/scripts/contact_sheet.py .
```
- `motion` must pass (no STATIC lines that should move).
- Open `build/sheet.png` and check every frame.
- **Pass criteria:** `motion check passed`; all screenshots checked.

### Step 10: Generate real audio, ASR check, re-check visuals
```bash
cd PROJ && PY build_audio.py && PY build_audio.py --asr && node render.mjs stills auto && PY SKILL/scripts/contact_sheet.py .
```
- **Pass criteria:** `mix + srt written`; letter errors 0 (or ASR SKIPPED if no GLM key).

### Step 11: Render the video and deliver
```bash
cd PROJ && node render.mjs video 6
```
- Output `WS/<output_name>.mp4` and `.srt`. Tell the user the paths, duration, content of each scene, and that you cannot listen to the audio so they should review pronunciation.

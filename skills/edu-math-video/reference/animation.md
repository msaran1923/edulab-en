# Writing animation: anim.js

First read the complete `template/anim.js` (all scenes of the sample problem, ~190 lines), then write new problems following its structure. `engine.js` provides all drawing functions; **do not modify engine.js**.

## How the files work together

`index.html` loads in order: `build/timeline.js` (generated by render.mjs from timeline.json) → `engine.js` → `anim.js` → `boot()`.
During rendering, `render.mjs` calls `renderFrame(t)` for every frame: draw background → current scene's `SC.<id>(lt, S)` → top-left label → subtitles. Scene transitions automatically cross-fade for 0.75 s.

`renderFrame(t)` must be **deterministic**: the same t produces the same picture. Do not use `Math.random()`, `Date.now()`, `setTimeout`, or variables that accumulate across frames. For randomness use `hash(n)`; for continuous motion use the global `NOW` (current seconds).

- intro scene: title y=150, English subtitle y=202, problem card auto-fits between y 240~730, condition chips `chip()` at y=790.

- If the figure is too large, reduce the scale factor (the sample's `K`); do not draw anything below y>860.

## Scene functions

```js
SC.solve = (lt, S) => {
  const { P, at } = S;
  fig({ len: 1, D: 1, CD: P(at(0, 0.5), 0.8) });        // start drawing CD halfway through sentence 0, finish in 0.8 s
  board(1);
  bl(0, 'Compute:', 0, lt, { c: C.gray, size: 32 });    // board title row
  bl(1, 'AB² = 3² + 4² = 25', at(0, 0.4), lt);          // start writing at 40% of sentence 0
  bl(3, 'CD = 2.5', at(1, 0.2), lt, { c: C.red, size: 50 });
  stamp(1560, 760, 'Answer: CD = 2.5', P(at(1, 0.7), 0.5), C.red, 50);
};
```
- `lt`: seconds since the start of this scene.
- `S.at(k, f)`: the moment f fraction of the way through narration sentence k (0-based). `at(k)` = start of sentence k.
- `S.P(a, dd=0.7)`: progress value that rises linearly from 0 to 1 over dd seconds starting at time a; 0 before, 1 after. Almost every function's `p` parameter consumes this value.
- `S.cue(k)`, `S.dur(k)`, `S.n` (number of sentences in this scene) are also available.
- Easing: `eio(x)` (slow-fast-slow), `eout(x)`, `back(x)` (with overshoot). Example: `lerp(a, b, eio(P(at(2), 1.5)))`.
- Show an element only during a time window: `grp(P(t0, 0.4) * (1 - P(t1, 0.4)), () => {...})`.
- Continuity between scenes: at the start of the next scene, set the end state of the previous scene directly to 1 (see sample `SC.key` with `fig({len: 1, right: 1, D: 1, CD: 1, ...})`).

**Write the figure as a function with switches** (the sample's `fig(st)`): each key in `st` is the progress 0~1 of an element (omit = do not draw). Each scene only decides which elements to turn on and when.

## engine.js API quick reference

All coordinates are canvas pixels; `o` is an optional parameter object. Colors: `C.ink / red / blue / green / yellow / purple / gray / pink`.
Color convention: given quantities blue, sought/answer red, auxiliary lines / key conclusions green, emphasis yellow.

**Drawing lines**
| Function | Description |
|---|---|
| `draw(pts, o)` | Hand-drawn polyline. `o.p` draw progress, `o.c` color, `o.w` width (4), `o.a` opacity, `o.dash:[12,10]` dashed, `o.rough` jitter (1.7, 0=straight), `o.single` single stroke, `o.seed` |
| `line(x1,y1,x2,y2,o)` | Segment |
| `arrow(pts, o)` | Polyline with arrowhead, `o.head` head size |
| `circ(cx,cy,r,o)` | Hand-drawn circle |
| `ellPts(cx,cy,rx,ry,a0,a1,n)` | Ellipse/arc point list, use with draw / fillPts |
| `quadPts(x0,y0,cx,cy,x1,y1)` | Quadratic curve point list |
| `fnPts(f, x0, x1, toScreen)` | Point list of function y=f(x) (use with `axes().S`) |
| `fillPts(pts, col, a)` | Fill polygon (use a=0.1~0.25 for translucent coloring) |
| `along(pts, u)` | Point at fraction u along polyline `{x,y,ang}` (moving point along path) |
| `flow(pts, o)` | Arrow V-shape moving along path (indicates direction of motion) |
| `mid(p,q)`, `mix2(p,q,t)`, `lerp`, `clamp` | Point operations |

**Geometric marks**
| Function | Description |
|---|---|
| `dot(x,y,col,r)` | Filled point |
| `ptLabel('A', q, dx, dy, p, col)` | Draw point at q and write letter at offset (dx,dy); offset toward outside of figure, ~30~40px |
| `rightM(V, A, B, col, size, p)` | Right-angle mark |
| `angM(V, A, B, col, r, p)` | Angle arc |
| `tickM(p, q, n, col, pp)` | Equal-length marks (n short ticks) |
| `paraM(p, q, col, pp)` | Parallel mark (> at midpoint) |

**Text**
| Function | Description |
|---|---|
| `txt(s, x, y, o)` | Text. `o.p` typewriter progress, `o.size`, `o.f` font (default ZH cute Chinese; `EN` handwritten English; `MF` formula), `o.al` 'center'/'left'/'right', `o.c`, `o.pop` pop progress, `o.bold`. Returns width |
| `lb(zh, en, x, y, o)` | Chinese + small English below |
| `board(p)` | Right-side lined board |
| `bl(i, str, t, lt, o)` | Board row i (may be fractional), typewriter from time t. `o.size` default 38 (emphasis 44~50), `o.c`. **Each row ≤ ~40 characters**, otherwise it overflows the board |
| `stamp(x, y, str, p, col, size, rot)` | Stamp effect (final answer) |
| `chip(str, x, col, p)` | Small condition label under the problem in the intro scene (y=790) |
| `bubble(x, y, str, p, o)` | Speech bubble |
| `token(ch, x, y, col, k)` | Circular character marker (for "A"/"B" in motion problems) |
| `puff(x, y, s, o)` | Mascot puff: `s` size (corner 0.5, ending 1.3), `o.look:[dx,dy]` look direction, `o.wave` wave, `o.mood:'wow'` |

**Explanation actions** (design method see visual-design.md)
| Function | Description |
|---|---|
| `bump(lt, t0, dur=1.2)` | Pulse 0→1→0 starting at t0: use with glow to flash when "mentioned" |
| `glow(pts, col, a, w=22)` | Highlighter: draw a thick translucent line **under** the element (call it before drawing the element) |
| `slideSeg(a, b, c, d, e, o)` | Copy of segment a-b translates+rotates+scales onto c-d (e = 0..1, use `eio(P(...))`): equal, parallel, corresponding |
| `movePoly(pts, dx, dy, rot, k)` | New point list after translating/rotating/scaling a polygon about its own centroid: congruence overlay, similarity scale |
| `tween(P0, P1, e)` | Interpolate between two point sets (morph, unfold) |
| `callout(from, to, p, col)` | Curved dashed arrow from a point on the figure to a board row |
| `flyText(str, from, to, e, o)` | Numeric label flies along an arc from the figure to the board ("substitute"); `blPos(i, dx)` gives the position of board row i |
| `countTo(v0, v1, e, dec)` | Number string that counts with progress |
| `camTween(A, B, e)` | Interpolate between two camera poses; `pitch: PI/2` is a true top view |

**Containers**
| Function | Description |
|---|---|
| `grp(a, fn)` | Draw the content of fn at opacity a (fade in/out) |
| `scaleAt(x, y, k, fn)` | Scale about (x,y) |

**Problem card**: `problemCard(p)`, `hiBox(box, col, t, lt)` (see next section).

**Coordinate system**:
```js
const ax = axes({ ox: 300, oy: 600, sx: 70, sy: 70, xr: [-3, 5], yr: [-2, 5], step: 1 });
ax.draw(P(0.3, 1.2), true);                                        // draw axes (second param true = grid)
draw(fnPts(x => (x - 1) ** 2 - 1, -1.2, 3.2, ax.S), { c: C.blue, w: 5, p: P(at(0), 1.5) });
ptLabel('P', ax.S([1, -1]), 30, 20, 1, C.red);                     // ax.S([x,y]) math coords → screen coords
```
Compute the ranges carefully: `ox + xr[0]*sx ≥ 60`, `ox + xr[1]*sx ≤ 880`, `oy - yr[1]*sy ≥ 150`, `oy - yr[0]*sy ≤ 850`.

**Solid geometry (oblique axonometric camera)**:
```js
CAM.cx = 470; CAM.cy = 520; CAM.s = 160; CAM.target = [0, 0, 1];   // set at the top of anim.js
// World coordinates: x right, y toward viewer (drawn below), z up
const G = { A: [-2, 0, 0], B: [2, 0, 0], P: [0, 0, 2], ... };
L3(G.A, G.B);                      // 3D segment
L3(G.A, G.C, { hidden: true });    // occluded edges as dashed (textbook convention); check screenshots to confirm which should be dashed
draw(arc3(G.O, G.A, G.P, 0.4), { c: C.red, w: 3 });   // 3D angle arc
const q = pr(G.P);                 // 3D point → screen [x,y], for ptLabel / fillPts
```
To slowly rotate the figure for more depth: in the scene `CAM.yaw = 0.2 + 0.14 * Math.sin(NOW * 0.42);` (set every frame to stay deterministic).

**Motion / moving-point problems**: compute position from a time parameter; do not accumulate frame by frame.
```js
const at_s = s => s <= 60 ? mix2(A, B, s / 60) : mix2(B, C_, (s - 60) / 80);   // distance s → screen position
const tau = lerp(-10, 7.5, eio(P(at(1), 3)));                                     // "problem time" in the animation
const pj = at_s(4 * (tau + 10));  token('A', ...pj, C.red);
```
Also show time and distance live in the upper-left of the figure area (`txt(\`t = ${tau.toFixed(1)} s\`, 90, 180, {al: 'left'})`).

## Problem image and highlight boxes

Top of `anim.js`:
```js
const PROBLEM = {
  src: 'problem.png', srcW: 1500, srcH: 240,          // actual pixel size of the image
  boxes: {                                            // source image pixel coords [x0, y0, x1, y1]; multi-line phrases get multiple boxes
    AC: [[773, 44, 915, 116]],
    mid: [[1123, 44, 1422, 116], [34, 124, 184, 196]],
  },
};
```
intro scene:
```js
problemCard(P(0.4, 0.7));                             // card + image (auto-scaled and centered)
hiBox(PROBLEM.boxes.AC, C.blue, at(1, 0.2), lt);      // box it when 20% through sentence 1
chip('AC = 3', 800, C.blue, P(at(1, 0.8), 0.5));      // small label below
```
Coordinate sources:
- **Text problem**: `make_problem_png.py --text ... --mark ...` directly outputs `srcW/srcH/boxes` and generates `problem.preview.png`; open and check. The phrases in `--mark` must match the characters in `--text` exactly (full-width/half-width, spaces).
- **Screenshot**:
  1. Multiple problems or large blank areas in the screenshot → `PY SKILL/scripts/problem_boxes.py crop raw.png x0 y0 x1 y1 PROJ/problem.png`.
  2. `problem_boxes.py grid PROJ/problem.png` → open `problem.grid.png`, lines every 50px, numbers every 100px, read the range of each condition.
  3. `problem_boxes.py check PROJ/problem.png '{"AC":[[x0,y0,x1,y1]], ...}'` → open `problem.check.png` and confirm the red boxes cover the text; if not, adjust the numbers and check again.
  4. If a phone photo is skewed or too dark, tell the user a clear screenshot is better; or regenerate the image as a text problem.

## Review checklist

First run `node render.mjs motion` (see visual-design.md); only after it passes look at the screenshots.

After every `stills auto` + `contact_sheet.py`, check each image against the list. **Write down what you actually see; do not check off from memory**. For unclear areas, open the individual `build/stills/*.png` directly with the image viewing tool:
- [ ] **Problem image text is complete**: zoom into the intro screenshot; no ☒/□ boxes, missing characters, or garbled text (missing fonts turn ² − √ etc. into boxes)
- [ ] **No JS errors** (render.mjs did not print `FAILED` / `PAGE ERROR`)
- [ ] **Does not cover subtitles**: all graphics, text, and mascot are at y ≤ 860
- [ ] **Does not overflow**: board text does not exceed the right border (x ≤ 1850); figure does not enter the board area
- [ ] **No overlap**: point letters, length labels, and formula labels do not obscure each other; readable where they cross lines
- [ ] **Synchronized**: in every screenshot (= near the end of a narration sentence), everything mentioned by that sentence has already appeared, and everything not yet mentioned has not
- [ ] **intro**: every sentence that reads the problem boxes the corresponding condition, and the box position is accurate
- [ ] **Figure complete**: every point, segment, and relation in the figure inventory at the top of the storyboard is drawn (if the problem says DE∥BC, DE must exist and must actually be parallel)
- [ ] **Correct**: numbers on the figure, board formulas, and subtitles match your Step 1 solution exactly; proportions are reasonable (right angles look like right angles, equal lengths look equal)
- [ ] **Ending**: outro has the answer; `zz_end.png` is complete
- [ ] At most ~9 board rows per scene; split into two scenes if more

To inspect intermediate animation states: `node render.mjs stills 12.5,13,13.5` (seconds can be looked up from the start/end of each sentence in `build/timeline.json`).

Browser live preview (optional, when the user wants to watch): open `index.html` in PROJ with any static server (e.g. `npx http-server PROJ` or `PY -m http.server`); it has a play button and progress bar.

## Common pitfalls
- Using a function name not defined in anim.js → screenshot reports `PAGE ERROR ... is not defined`, and the second half of that frame is blank.
- Using `NOW` or `lt` outside `SC.xxx` (at the top level) to compute things → computed only once, will not move.
- Passing a progress value (0~1) as the t argument of `bl()` instead of a time: `bl(1, '...', at(0, 0.5), lt)` is correct.
- Passing an absolute second value other than `at(k)` as the first argument of `P()` → misaligned after the voice-over changes.
- Problem image does not appear → `PROBLEM.src` filename is wrong, or srcW/srcH does not match the actual size (highlight boxes will be offset as a whole).
- Many `fillPts` stacked with opaque colors → covers the lines underneath; use a ≤ 0.25 for coloring.
